# USS-013 — Controlled Independent Adoption

**Status:** Draft specification derived from ratified workshop decision; Operator approval required before normative release.

**Purpose:** Separate publishing USS from each system adopting USS.

## Rules
1. **013-01** — Use approved Git releases with changelog and impact assessment for normative changes.
2. **013-02** — Each system pins its own adopted release and may migrate independently.
3. **013-03** — Permit verified mechanical/editorial updates without changing meaning.
4. **013-04** — Require Operator approval for normative changes and release publication.
5. **013-05** — Track COMPLIANT, PARTIAL, EXEMPT, NOT_APPLICABLE and UNKNOWN with evidence.
6. **013-06** — Record justified exceptions with owner, risk and review date.

## Prohibited
- No automatic cross-system rollout after USS publication.
- No claiming COMPLIANT merely from a version pin.

## Defaults and limits
- Apply risk-proportionate limits. See `governance/DEFAULTS_AND_TOKEN_BUDGETS.md`. Proposed numbers are **not ratified**.
- Exceptions require explicit rationale and appropriate authorization.

## Verification
Prove a draft change cannot become normative without approval.
